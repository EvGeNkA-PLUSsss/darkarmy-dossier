## Как искать причину

1. **Консоль сервера** — там печатается bootstrap-пароль, порт, путь проектов и ошибки старта.
2. **`data/log.txt`** — JSON-строки; ищите `"level":"ERROR"` и `uncaughtException`.
   В PowerShell: `Select-String -Path data\log.txt -Pattern '"level":"ERROR"' | Select-Object -Last 20`.
3. **DevTools браузера** → Network: статус и тело ответа; Console — ошибки JS.
4. **`/api/health`** — быстрый ответ, живы ли БД/каталоги/пользователи.
5. **Админка → Обзор** — размеры, статус Ollama, модели, бэкапы.
6. **`journalctl -u darkarmy-dossier -n 100`** для systemd.

## Запуск и порты

| Симптом | Причина | Решение |
|---|---|---|
| `EADDRINUSE: address already in use 127.0.0.1:7561` | порт занят другим процессом | найти и остановить: `Get-NetTCPConnection -LocalPort 7561` → `Stop-Process -Id <pid>`; либо сменить `PORT` |
| `http://127.0.0.1:7561` не открывается | сервер не запущен / другой порт | проверьте консоль: `DarkArmy Dossier: http://…:PORT` |
| Сайт открывается, но пустой экран | ошибка JS или 404 статики | DevTools Console; проверьте, что `public/app.js` отдаётся (200) |
| После рестарта вкладка «сама перезагружается» | `/api/version` изменился (build = время старта) | это нормальное поведение |
| Сервер падает сразу после старта | `uncaughtException` | смотрите `data/log.txt`, последняя строка со стеком |
| `EACCES` при старте | нет прав на `DATA_DIR`/`PROJECTS_ROOT` | `chown`/`icacls`, запуск не от root |
| Порт 7561 доступен из интернета | `BIND_HOST=0.0.0.0` без прокси | поставьте `127.0.0.1` + reverse proxy |

## Конфигурация и `.env`

| Сообщение | Причина | Решение |
|---|---|---|
| `SESSION_SECRET обязателен в production. Задайте через env.` | `NODE_ENV=production`, а секрет пуст | задайте `SESSION_SECRET` (64 hex) |
| `[config] SESSION_SECRET не задан — генерирую временный` | dev-режим без секрета | нормально для разработки; сессии не переживут рестарт |
| `invalid IP address: true` (старые версии) | `TRUST_PROXY=true` строкой | обновите код или поставьте `TRUST_PROXY=1` |
| Настройки «не применяются» | сервер запущен без `--env-file=.env` | `node --env-file=.env server.js`, `npm run start:prod` или systemd `EnvironmentFile` |
| `.env` в git | забыли `.gitignore` | удалите из индекса (`git rm --cached .env`), смените секреты |
| `ADMIN_PASSWORD` не сработал | пользователи уже существуют | bootstrap выполняется только при пустой таблице `users`; смените пароль через профиль или создайте пользователя в админке |

Проверка, что окружение прочитано:

```bash
node -e "console.log(require('./config'))"
```

## Права доступа и файлы

| Симптом | Причина | Решение |
|---|---|---|
| `403 forbidden` на `/api/tree` | вы не участник проекта | добавьте себя в проект (создатель/админ) |
| `403` на создание/правку | роль `member` | нужна роль `editor`/`creator` |
| `403` на админку | роль не `admin` | войдите администратором |
| `403` при загрузке | нет права edit | проверьте роль в проекте |
| `400 bad path` / `403 forbidden` на файле | путь с `..`, NUL или выход за корень | используйте относительный путь без `..` |
| Файл с `%` в имени не открывается | двойное декодирование (старый баг) | обновляйте версию; в актуальном коде Express 5 декодирует один раз |
| Кириллица в имени «кракозябрами» | latin1→utf8 в multipart | актуальный код исправляет (`decodeUploadFilename`); проверьте версию |
| «Файл не найден» после переименования | устаревшее дерево | нажмите «Обновить»/перезагрузите страницу |
| Нельзя удалить создателя проекта | защита бизнес-правила | сначала смените создателя (передайте роль `creator` другому), либо удалите проект админом |
| Нет доступа к `data/` у сервиса | `ProtectSystem=full` и `ReadWritePaths` | добавьте каталоги в `ReadWritePaths` |

## SQLite и «database is locked»

| Симптом | Причина | Решение |
|---|---|---|
| `SQLITE_BUSY: database is locked` | второй процесс пишет в ту же БД | держите **один** экземпляр приложения; проверьте `pm2 list`, systemd, запущенный вручную `node` |
| Блокировки при бэкапе | копирование `dossier.db` вручную при работающем сервере | используйте `npm run backup` (backup API) или остановите сервис |
| Медленно всё | `data/` на сетевом диске/SMB | перенесите на локальный SSD; WAL плохо работает на сетевых ФС |
| БД «похудела» после рестарта | данные были в `-wal` | это нормально, WAL схлопывается; смотрите логический размер в админке |
| `SQLITE_CORRUPT` | обрыв питания/диска/копирование «на горячую» | восстановите из бэкапа; проверьте `PRAGMA integrity_check` |
| Долгий старт после обновления | миграция JSON→SQLite на большом объёме | дождитесь, в логе будет `[storage] JSON → SQLite: …` |
| Файл `dossier.db-wal` огромный | долгие транзакции/редкие чекпоинты | перезапустите сервис (checkpoint), проверьте размер `telemetry`/`changes` |

Проверка целостности:

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/dossier.db');console.log(db.prepare('PRAGMA integrity_check').get());db.close()"
```

⚠️ Никогда не запускайте два процесса на одном `DATA_DIR` — это главная причина
повреждений и «залипших» блокировок.

## Ollama и Darcus

| Симптом | Причина | Решение |
|---|---|---|
| «Проверить связь» → `ok:false` | Ollama не запущена/другой URL | `ollama serve`, `curl http://localhost:11434/api/tags` |
| `ECONNREFUSED 127.0.0.1:11434` | сервис не слушает | `systemctl status ollama` / перезапуск |
| `Ollama не ответила за 180 с` | модель грузится, мало RAM, CPU | увеличить `timeout`, взять модель меньше (`e2b`/`3b`), закрыть лишнее |
| `socket hang up` | Ollama перезапустила runner | повтор автоматически; если постоянно — уменьшите `numCtx` |
| Ответ пустой | модель не справилась с промптом | сменить модель, начать новый чат, уменьшить контекст |
| Контекст «90%+» и ответы хуже | промпт не влезает в `numCtx` | новый чат, меньше вложений, увеличить `numCtx` |
| `Модель "…" не является vision-моделью` | текстовая модель в `visionModel` | `qwen2.5vl:3b`, `gemma4:e4b`, `llava`, `minicpm-v` |
| OCR возвращает «не могу»/`<|img|>` | длинный системный промпт или модель без vision | актуальный код использует компактный промпт; проверьте модель через `/api/show` |
| Семантика не находит | `embedModel` недоступна | `ollama pull nomic-embed-text`, переиндексация |
| `Darcus: слишком много запросов` | 20/мин | подождите минуту |
| `subscription-required` | нет подписки | активировать код / выдать в админке |
| Действие Darcus не выполнилось | невалидный JSON/путь/нет прав | смотрите плашку с ошибкой; повторите запрос |
| `generate_doc` из чата не работает | старый кэш `app.js`, нет подписки или тип не указан в `system` | `Ctrl+F5`, проверить подписку, добавить `generate_doc` в промпт `system` |
| `ai-config.json` «сбросился» | битый JSON → `DEFAULT_CONFIG` | восстановите файл из бэкапа, проверьте JSON-валидность |
| `В production запрещены приватные адреса` | `NODE_ENV=production` + localhost Ollama | задайте `DARCUS_ALLOWED_HOSTS=localhost,127.0.0.1` |

Проверка без приложения:

```bash
curl -s http://localhost:11434/api/tags
curl -s http://localhost:11434/api/chat -d '{"model":"gemma4:e4b","messages":[{"role":"user","content":"привет"}],"stream":false}'
curl -s http://localhost:11434/api/embeddings -d '{"model":"nomic-embed-text","prompt":"тест"}' | head -c 200
```

## Silero TTS

| Симптом | Причина | Решение |
|---|---|---|
| `/api/darcus/tts` → `500 TTS сервис не настроен` | пуст `tts.url` | админка → Голос → TTS URL `http://127.0.0.1:8765/tts` |
| TTS молчит, ошибок нет | автозапуск браузера заблокирован | нажмите динамик ещё раз (первое касание разблокирует Web Audio) |
| `Silero TTS недоступен: …` | Python-сервер не запущен | `python scripts/silero_tts_server.py --port 8765` |
| Первый синтез очень долгий | модель скачивается через `torch.hub` | подождите; далее модель в кэше |
| `ModuleNotFoundError: torch` | не установлены зависимости | `python -m pip install torch numpy` |
| Голос читает латиницу неправильно | старый код без нормализации | в актуальной версии `prepareTtsText` переводит в кириллицу |
| `ok:false` на `/health` | модель ещё не загружена | первый `POST /tts` загружает её; дождитесь |
| Порт 8765 занят | другой процесс | сменить порт в скрипте и в конфиге (`--port`) |

## Whisper STT и кодировка

| Симптом | Причина | Решение |
|---|---|---|
| «кракозябры»/`?????` в тексте | консоль Windows cp1251 | актуальный скрипт пишет UTF-8 (`PYTHONIOENCODING`, `PYTHONUTF8`) и выводит через `sys.stdout.buffer`; обновите код |
| `faster-whisper не установлен` | пакет отсутствует | `python -m pip install faster-whisper` или кнопка «Установить Whisper (авто)» |
| `faster-whisper exit 1` | битое аудио/нет модели | проверьте `data/stt-*.webm`, скачайте модель (`base`/`small`) |
| `faster-whisper timeout` | запись слишком длинная/медленный CPU | короче фрагмент, модель `base`, больше CPU |
| Распознаёт с ошибками в терминах | нет hotwords | они включены по умолчанию; можно задать `STT_HOTWORDS` |
| `Whisper не настроен (WHISPER_BIN / WHISPER_MODEL)` | выбран whisper.cpp без путей | задайте переменные или переключитесь на faster-whisper |
| Микрофон не пишет | нет разрешения/HTTP | разрешите доступ, HTTPS или системный диктофон |
| `500 no audio` | пустое тело запроса | проверьте, что браузер отправил аудио |

Проверка скрипта вручную:

```bash
python scripts/faster_whisper_stt.py base data/test.webm ru
# {"text":"…","language":"ru"}
```

## Микрофон и HTTPS

| Симптом | Причина | Решение |
|---|---|---|
| Кнопка микрофона не реагирует | `getUserMedia` недоступен (HTTP в LAN) | HTTPS-порт (`HTTPS_PORT`) или серверный Whisper + `<input capture>` |
| Браузер не спрашивает разрешение | сайт не в secure context | `https://` или `localhost` |
| `HTTPS: PFX не найден — HTTPS-порт не запущен` | неверный путь/файл | проверьте `HTTPS_PFX`, сгенерируйте PFX |
| Предупреждение сертификата | самоподписанный сертификат | примите или установите `.cer` в доверенные |
| Микрофон работает, но TTS молчит | нет русского голоса в ОС | установите русский голос или Silero |
| `Permissions-Policy` блокирует | заголовок `microphone=()` | это политика для iframe/сторонних контекстов; `getUserMedia` на своём origin работает |

## PWA не устанавливается

| Симптом | Причина | Решение |
|---|---|---|
| Нет иконки установки | HTTP (не localhost) | HTTPS или `localhost`/`127.0.0.1` |
| «Установка недоступна» | `beforeinstallprompt` не сработал | установите через меню браузера |
| На iOS нет кнопки | Safari не поддерживает `beforeinstallprompt` | «Поделиться» → «На экран Домой» |
| Service worker не регистрируется | нет HTTPS или ошибка 404 `/sw.js` | проверьте `curl -I /sw.js`, откройте `chrome://serviceworker-internals` |
| Старая версия после обновления | кэш `da-pwa-v1` | `Ctrl+F5`, DevTools → Application → Service Workers → Update |
| Офлайн пустой экран | API не кешируется (так задумано) | это норма: офлайн доступна только оболочка |
| Манифест не читается | неверный MIME/путь | `curl -I /manifest.webmanifest` → `application/manifest+json` или `application/json` |

## nginx и reverse proxy

| Симптом | Причина | Решение |
|---|---|---|
| `502 Bad Gateway` | Node не запущен или не тот порт | `systemctl status darkarmy-dossier`, `curl 127.0.0.1:7561/api/health` |
| `504 Gateway Time-out` | долгий запрос/стрим | `proxy_read_timeout 1h` для `/api/events` и `/api/darcus/chat` |
| `413 Request Entity Too Large` | `client_max_body_size` | поставьте `2048m` (или свой лимит) |
| SSE приходит «пачкой»/молчит | буферизация прокси | `proxy_buffering off`, `X-Accel-Buffering: no` (уже отдаётся сервером) |
| Соединение рвётся каждые 60 с | таймаут прокси | увеличить `proxy_read_timeout`/`send_timeout` |
| Неверный IP в логах/лимитах | нет `X-Forwarded-For`/`TRUST_PROXY` | заголовки + `TRUST_PROXY=1` |
| `Redirect loop` | HTTP→HTTPS на обоих уровнях | оставьте редирект только на прокси |
| `CSP` ломает страницу | прокси добавляет свои заголовки | не дублируйте `Content-Security-Policy` |
| Не работают share-ссылки | прокси режет `/s/…` | проверьте `location /` и логи |
| WebSocket не работает | он и не нужен | приложение использует SSE; `Upgrade` не требуется |

Проверка конфигурации:

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -I https://dossier.example.com/api/health
```

## Загрузки и лимиты

| Симптом | Причина | Решение |
|---|---|---|
| `413 Файл X МБ превышает лимит N МБ.` | лимит участника | админка → Настройки → лимит загрузки |
| `413` сразу, без загрузки | `Content-Length` больше лимита | это ранняя проверка, работает как задумано |
| `413 Слишком большой запрос` на JSON | тело >20 МБ | уменьшите пакет (телеметрия/импорт) |
| Загрузка «висит» | большой файл + медленный диск | подождите; проверьте свободное место |
| `data/tmp` забит | старые временные файлы | перезапуск чистит `tmp`; проверьте права |
| Файл загрузился с ` (1)` | имя уже существовало | это нормальная дедупликация |
| Вложение не открывается | чужой scope/нет прав | откройте из своего чата/проекта |
| `Запрещённый тип файла` | чёрный список (exe/bat/…) | заархивируйте или смените расширение осознанно (но это обход политики) |

## Совместное редактирование

| Симптом | Причина | Решение |
|---|---|---|
| Индикатор «редактируют» пуст | SSE не подключён | DevTools → Network → `events` (pending) |
| Правки не приходят | разные проекты/файлы | сверьте `projectId` и путь |
| `410 session ended` | сессия закрыта (все ушли/рестарт) | снова нажмите «Ред.» |
| Текст откатывается | last-write-wins | один редактор за раз на один абзац; сохраняйте чаще |
| Двойной счётчик устройств | дублированная вкладка с тем же `sessionStorage` | закройте лишнюю вкладку |
| «Сохранить» не срабатывает | нет права edit | проверьте роль |
| Черновик «воскресает» | `da_openEditors` в localStorage | сохраните/закройте редактор корректно |
| Текст потерян после падения сервера | не успел flush (≤0,5 с) | используйте `Ctrl+S` перед рискованными действиями |

## Поиск и индексация

| Симптом | Причина | Решение |
|---|---|---|
| Поиск только по точным словам | нет эмбеддингов | проверьте `embedModel`, «Переиндексировать» |
| Ничего не находит | запрос <2 символов | введите минимум 2 символа |
| Не находит в PDF/DOCX | извлечение не поддерживает файл | проверьте размер (≤20 МБ) и формат |
| Не находит текст на картинке | нет OCR в кэше | откройте изображение (OCR по кнопке) или загрузите заново |
| Медленно | синхронный обход ФС | уменьшите проект, отключите семантику (`embedModel` пуст) |
| `Слишком много запросов` | 30/мин | подождите |
| Индексация «0 ошибок, но пусто» | файлы не текстовые/пустые | проверьте `data/embeddings.json` |

## Почта ошибок API

| Ответ | Что значит | Что делать |
|---|---|---|
| `401 unauthorized` | нет сессии | войдите заново |
| `403 forbidden` | нет прав | роль/проект/чужой объект |
| `403 banned` | бан | снимите наказание в админке |
| `403 muted` | мьют | снимите мьют |
| `403 chat-disabled` | общий чат только для админов | админка → Настройки → Общий чат |
| `404 not found` | объект удалён | обновите страницу |
| `409` | конфликт (код/логин/папка/файл) | устраните конфликт |
| `410 session ended` | сессия правок закрыта | переоткройте редактор |
| `413` | размер | уменьшите файл/запрос |
| `429` | лимит | подождите |
| `500 internal error` | исключение | смотрите `data/log.txt` |
| `502` | ошибка модели | повторите, смените модель |
| `503 degraded` | не здоров | `/api/health` → какая проверка false |
