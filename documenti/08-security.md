## Модель угроз и границы доверия

| Зона | Доверие | Что защищаем |
|---|---|---|
| Браузер пользователя | не доверяем | сессии, права, содержимое чужих проектов |
| HTTP-запросы | не доверяем | пути, MIME, размеры, ID объектов |
| reverse proxy | доверяем только при `TRUST_PROXY` | IP клиента, схему |
| SQLite и `DATA_DIR` | доверяем на уровне ОС | хеши паролей, переписку, телеметрию |
| `PROJECTS_ROOT` | доверяем на уровне ОС | файлы пользователей |
| Ollama / Silero / Python | локальные сервисы | SSRF, подстановка URL |
| Внешние сайты (DDG, Википедия) | **не доверяем** | prompt injection в RAG/веб-контекст |

Ключевой принцип: **любой пользовательский ввод — недоверенный**, включая имена файлов,
пути, MIME, base64-картинки, ACTION-блоки ИИ и содержимое загруженных документов.

## Аутентификация и сессии

| Свойство | Значение |
|---|---|
| Cookie | `sid` |
| `httpOnly` | да |
| `sameSite` | `strict` |
| `secure` | да в `NODE_ENV=production` |
| Срок | 7 дней (`maxAge`) |
| Хранилище | SQLite-таблица `sessions` (переживает рестарт) |
| Подпись | `SESSION_SECRET` (обязателен в production) |
| Пересоздание | `req.session.regenerate` при входе и регистрации |
| Проверка бана | на каждом запросе; при бане сессия уничтожается |
| Роль | перечитывается из БД на каждом запросе (не доверяем данным сессии) |

Поведение при ошибках:

- нет `SESSION_SECRET` в production → приложение **не стартует** с явной ошибкой;
- в development секрет генерируется случайно (сессии не переживают рестарт);
- `TRUST_PROXY` парсится в `false | true | число | строку` (`config.js`), что исключает
  падение `invalid IP address`.

Защита от перебора:

- bcrypt-сравнение выполняется даже для несуществующего логина (фиктивный `DUMMY_HASH`) —
  нет разницы во времени ответа;
- лимит `LOGIN_MAX_ATTEMPTS` (10) за 15 минут на IP/логин;
- лимит регистрации 15/час.

## Пароли

`validatePassword` (общая для регистрации, создания пользователя, смены пароля):

| Правило | Сообщение |
|---|---|
| ≥ 8 символов | «Пароль должен быть минимум 8 символов» |
| ≤ 200 символов | «Пароль слишком длинный» |
| строчная буква (латиница/кириллица) | «должен содержать строчную букву» |
| заглавная буква | «должен содержать заглавную букву» |
| цифра | «должен содержать цифру» |
| не один повторяющийся символ | «не должен состоять из одного символа» |
| не последовательность (`12345678`, `qwertyuiop`, `йцукенгшщзхъ`, …) | «не должен быть последовательностью» |
| не из списка частых (около 100 значений) | «слишком распространён» |
| не содержит логин | «не должен содержать логин» |

Хранение: `bcryptjs`, cost 10. API никогда не возвращает `password` (список пользователей
маппится с исключением поля).

Первый администратор: пароль из `ADMIN_PASSWORD` или случайный (24 символа base64url).
Печатается **только в консоль**, в `data/log.txt` не попадает. Флаг
`mustChangePassword: true` выставляется, но принудительной смены при входе нет —
это ответственность администратора ⚠️.

## Роли сайта и роли проекта

### Роль сайта (`user.role`)

| Роль | Возможности |
|---|---|
| `member` | всё в рамках проектов, где он участник; свои тикеты, запросы, жалобы, баги |
| `admin` | доступ ко всем проектам, админ-панель, журнал, откат, бэкап, экспорт/импорт, реклама, подписки, телеметрия, Darcus-конфиг, голос, баги, удаление проектов и пользователей; Darcus без подписки |

### Роль в проекте (`project.members[].role`)

| Роль | Чтение | Редактирование | Управление |
|---|---|---|---|
| `member` | ✓ | — | — |
| `editor` | ✓ | ✓ | — |
| `creator` | ✓ | ✓ | ✓ |
| admin сайта | ✓ | ✓ | ✓ (для любого проекта) |

Особые правила:

- создателя проекта нельзя понизить или удалить;
- нельзя снять роль с последнего администратора сайта и удалить его;
- нельзя удалить собственный аккаунт, если он последний администратор;
- нельзя наказать себя.

## projectGuard: проверка доступа к проекту

```js
projectGuard(level = 'read', from = 'anywhere')
```

1. Определяет `projectId` из `body` / `query` / `params` (в зависимости от `from`).
2. Нет `projectId` → `400 {"error":"projectId required"}`.
3. Проект не найден → `404 {"error":"project not found"}`.
4. Проверяет уровень:
   - `read` — участник или admin;
   - `edit` — `editor`/`creator` или admin;
   - `manage` — `creator` или admin.
5. Нет прав → `403 {"error":"forbidden"}`.
6. Кладёт в `req.project` и `req.projectRoot`, создаёт папку проекта при необходимости.

Типичные связки:

| Маршрут | Guard |
|---|---|
| `/api/tree`, `/api/raw`, `/api/search` | `read` |
| `/api/create`, `/api/mkdir`, `/api/rename`, `/api/write`, `/api/delete`, `/api/move`, `/api/upload` | `edit` |
| `/api/edit/*` | `edit` |
| `/api/projects/:id/activity` | `manage` (внутри обработчика) |
| `/api/projects/:id` (GET) | проверка `canReadProject` вручную |
| `/api/projects/:id` (PATCH/DELETE) | `canManageProject` / `requireRole('admin')` |

Объекты, у которых нет `projectId` в пути (вложения, share, уведомления, задачи),
проверяются точечно внутри обработчика — по владельцу, scope или членству.

## CSRF, CORS, SameSite

- **CSRF-токенов нет** ❌. Защита: `SameSite=strict` + `httpOnly` + отсутствие CORS.
- Все изменяющие операции — `POST/PATCH/DELETE` с JSON-body (кроме multipart-загрузок).
- `express.urlencoded` включён, поэтому теоретически возможна form-отправка, но
  `SameSite=strict` не отправит cookie с чужого сайта в современных браузерах.
- Нет проверки `Origin`/`Referer` и нет double-submit cookie.
- CORS не настроен: кросс-доменные запросы с credentials не пройдут.
- Встраивание в iframe запрещено: `X-Frame-Options: DENY` и `frame-ancestors 'none'`.

Рекомендация для усиления (не реализовано): добавить проверку `Origin` для изменяющих
запросов и/или CSRF-токен в формы.

## Безопасность файлов и путей

### `safeJoin(root, rel)`

1. `rel` должен быть строкой без `\0`.
2. `\` нормализуется в `/`.
3. `path.resolve(root, rel)` без ведущих `/`.
4. Результат обязан равняться `root` или начинаться с `root + path.sep`, иначе `forbidden`.

Дополнительно для `GET /files/:projectId/*filePath`:

- `fs.realpath` и повторная проверка префикса (защита от симлинков);
- отдача только если это файл.

### Отдача файлов (`sendProjectFile`)

| Категория | Content-Type | Disposition |
|---|---|---|
| `png,jpg,jpeg,gif,webp,bmp,ico` | как есть | inline |
| `svg` | `image/svg+xml` + CSP `default-src 'none'; style-src 'unsafe-inline'; img-src data:` | inline |
| `pdf` | `application/pdf` | inline |
| `md,txt,csv,log,json,yml,yaml,ini,conf,sh,env,html,htm,shtml,xhtml,xht,xml,js,mjs,cjs,jsx,ts,tsx,vbs,hta,chm,jar,swf,css,svgz,bat,ps1,py,sql` | `text/plain; charset=utf-8` | inline |
| всё остальное | `application/octet-stream` | attachment |

Это закрывает stored XSS: `.html`, `.shtml`, `.svgz`, `.xht`, `.xml` не исполняются
в origin приложения.

### Вложения чата

- Content-Type вычисляется **по расширению**, а не по клиентскому MIME;
- инлайн разрешён только для `png/jpg/jpeg/gif/webp/bmp/ico` (SVG — нет);
- CSP на ответе: `default-src 'none'; img-src 'self'; style-src 'unsafe-inline'`;
- доступ по scope (`general`/`project:<id>`/`ticket:<id>`) + владелец + админ;
- отказ доступа логируется в телеметрию (`attach-access-denied`).

## Загрузки и вложения

| Угроза | Мера |
|---|---|
| Заполнение диска | ранняя проверка `Content-Length`, лимит настроек, жёсткий cap 2 ГБ, `rateLimitUpload`, очистка `data/tmp` при старте и при ответе ≥400 |
| Path traversal в имени | `decodeUploadFilename` + `safeFileName` + `path.basename` |
| Исполняемые вложения | чёрный список: `exe,bat,cmd,sh,ps1,vbs,jar,msi,app,dll,scr,com,pif,hta,cpl` |
| Подмена MIME | MIME определяется по расширению при отдаче |
| Коллизия имён | суффикс ` (1)`, ` (2)` |
| Утечка чужого вложения | scope + владелец + админ, `attach-file` требует прав |
| Мусор в `data/tmp` | `cleanupRejectedUpload` удаляет файл при статусе ≥400 |

Ограничения:

- **антивирусной проверки нет** ❌;
- содержимое загруженных файлов не анализируется на вредоносный код (кроме OCR);
- SVG рекламы отдаётся с CSP, но это всё равно SVG из админки — доверяйте только админам.

## Заголовки и CSP

Устанавливаются на каждый ответ:

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: same-origin
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
X-Robots-Tag: noindex, nofollow
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload   (production)
```

CSP (только для запросов с `Accept: text/html`):

```
default-src 'self';
script-src 'self';
script-src-attr 'none';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self' data:;
connect-src 'self';
frame-src 'self';
object-src 'none';
base-uri 'self';
form-action 'self';
frame-ancestors 'none'
```

Особенности:

- `script-src 'self'` без `unsafe-inline` — все скрипты вынесены в файлы, библиотеки
  лежат в `public/vendor` (нет CDN);
- `script-src-attr 'none'` — inline-обработчики атрибутами запрещены;
- `style-src 'unsafe-inline'` разрешён (в разметке есть inline-стили) — это ослабление,
  но не позволяет исполнять JS;
- `X-Powered-By` отключён.

## SSRF-защита Ollama

URL Ollama задаётся в конфиге и может быть изменён только администратором, но всё равно
валидируется (`validateOllamaUrl`) при сохранении, тесте и запросе моделей:

1. только `http:`/`https:`;
2. блокируются `169.254.169.254` и `metadata.google.internal`;
3. при `DARCUS_ALLOWED_HOSTS` — хост должен совпасть или быть поддоменом из списка;
4. в production без списка запрещены приватные адреса и `*.local`.

Также защищены от подмены:

- `/api/darcus/test` не принимает URL из тела — только из сохранённого конфига;
- `/api/darcus/models` строит URL из конфига, а не из запроса;
- редиректы при `httpRequest` поддерживаются (до 300-х) — ⚠️ это может быть использовано
  для обхода проверки, если разрешённый хост отдаёт редирект на приватный; риск низкий,
  так как URL задаёт администратор.

## Секреты и их хранение

| Секрет | Где | В git |
|---|---|---|
| `SESSION_SECRET` | `.env` / `EnvironmentFile` systemd | нет (`.gitignore`) |
| `HTTPS_PFX_PASS` | `.env` | нет |
| `ADMIN_PASSWORD` | `.env` (одноразово) | нет |
| PFX-файл | `data/tls/dossier.pfx` | нет (`data/` в `.gitignore`) |
| Хеши паролей | `data/dossier.db` (`users.payload`) | нет |
| Токены share-ссылок | SQLite `documents.shares` | нет |
| Коды приглашений/подписок | SQLite `documents` | нет |
| Переписка, телеметрия | SQLite | нет |

Правила:

- не коммитить `.env`, `data/`, `backups/`, `*.log`, `data/tls/*`, `__pycache__`;
- в документации и тикетах указывать **только имена** переменных, не значения;
- при утечке `SESSION_SECRET` — сменить и перезапустить (все сессии станут недействительны);
- PFX-пароль не хранить в репозитории и в командной строке (используйте `.env`);
- bootstrap-пароль администратора не пишется в лог, но остаётся в истории консоли/`journalctl`
  — после первого входа смените его и очистите историю.

## Логи, журнал и телеметрия

Access-log (`data/log.txt`, JSON-строки):

- пишутся метод, URL, статус, время, пользователь, роль, IP, User-Agent, Referer;
- **не** пишутся статика и 304;
- share-токены и параметры `token/invite/code/secret` редактируются (`redactUrl`);
- ротация при 10 МБ, хранятся 5 архивов.

Журнал изменений:

- append-only в SQLite, 5 000 записей;
- для секретных файлов (`SENSITIVE_FILE_RE`: `.env*`, `*.pem|key|pfx|p12|kdbx`,
  `id_rsa*`, `*secret*`, `*credentials*`, `*password*`, `config.json`, `settings.json`,
  `users.json`, `subscriptions.json`, `shares.json`, `invites.json`) содержимое
  заменяется на `[REDACTED: sensitive file]`;
- длинные `before/after` обрезаются до 32 КБ;
- откат отредактированных записей запрещён.

Телеметрия:

- события `request`, `login`, `logout`, `register`, `client-info`, `password-change`,
  `self-delete`, `attach-upload`, `attach-access-denied`, `chat-message-delete`;
- содержит IP, User-Agent, пути запросов и клиентские характеристики (экран, TZ, платформа);
- **это персональные данные** — доступ только администратору, лимит 2 000 событий
  на пользователя, есть очистка (`POST /api/telemetry/:username/clear`).

## HTTPS

Варианты:

1. **Reverse proxy** (рекомендуется): Caddy/nginx терминируют TLS, приложение слушает
   `127.0.0.1`. См. [10-deployment-ubuntu.md](10-deployment-ubuntu.md).
2. **Встроенный HTTPS-порт** (`HTTPS_PORT`, PFX) — для локальной сети и микрофона.
   Не заменяет прокси для интернета.

Обязательно:

- `NODE_ENV=production` → `secure` cookie + HSTS;
- `TRUST_PROXY` соответствует числу прокси (иначе неверный IP в лимитах и логах);
- редирект HTTP→HTTPS на прокси;
- TLS 1.2+ (в nginx-конфиге `TLSv1.2 TLSv1.3`);
- HSTS на прокси и в приложении.

⚠️ Если открыть приложение по HTTP в интернет, cookie без `secure` и пароль уйдут
открытым текстом. Не делайте так.

## Бэкапы и восстановление

- `npm run backup` — консистентная копия SQLite + `data/` + `PROJECTS_ROOT` в `BACKUP_DIR`
  с ротацией (по умолчанию 7 копий);
- бэкапы содержат **хеши паролей, переписку и телеметрию** — храните их с теми же правами,
  что и `data/`, и не выкладывайте в публичные места;
- шифрование бэкапов не реализовано ❌ (используйте шифрование диска/архива средствами ОС);
- проверяйте восстановление не реже раза в месяц;
- перед обновлением и импортом метаданных — обязательный бэкап;
- экспорт `/api/admin/export` не содержит журнал/телеметрию и не заменяет бэкап.

## Известные остаточные риски

| Риск | Уровень | Комментарий |
|---|---|---|
| Нет MFA/SSO | средний | один пароль = весь аккаунт |
| Нет CSRF-токена | низкий-средний | компенсируется `SameSite=strict` |
| `style-src 'unsafe-inline'` | низкий | нельзя исполнить JS, но можно подменить вид |
| Нет антивируса для загрузок | средний | файлы хранятся как есть, отдаются безопасно |
| Prompt injection через RAG/веб | средний | ACTION подтверждается вручную; режим «⚡ Авто» снимает защиту |
| Один процесс, нет изоляции тенантов на уровне ОС | низкий | все проекты в одном `PROJECTS_ROOT` |
| Телеметрия хранит IP/UA | средний (приватность) | нужна политика хранения и очистка |
| Пароль администратора может остаться в истории консоли | средний | сменить и очистить историю |
| Нет ограничения числа проектов/файлов на пользователя | низкий | возможен «disk fill» в рамках лимита загрузки |
| Реклама-SVG | низкий | загружает только админ |
| Нет аудита действий администратора вне журнала | низкий | журнал пишет `admin-import`, `backup`, `revert` и т.п. |

---

## Чек-лист безопасности

Перед публикацией в интернет:

- [ ] `NODE_ENV=production`, `SESSION_SECRET` — уникальный, ≥32 байта;
- [ ] `BIND_HOST=127.0.0.1`, наружу — только HTTPS reverse proxy;
- [ ] `TRUST_PROXY` = реальное число прокси (обычно `1`), не `true`;
- [ ] пароль `admin` сменён, bootstrap-пароль удалён из истории/journalctl;
- [ ] `data/`, `PROJECTS_ROOT`, `BACKUP_DIR` закрыты правами ОС (`chmod 700`, владелец — сервисный);
- [ ] `.env` с `chmod 600`, не в git;
- [ ] PFX и его пароль не в репозитории;
- [ ] HSTS и `X-Robots-Tag` присутствуют (проверить `curl -I`);
- [ ] CSP отдаётся для HTML (проверить `curl -I -H "Accept: text/html" /`);
- [ ] HTML/JS/SVGZ отдаются как `text/plain` (проверить загрузкой `poc.shtml`);
- [ ] `DARCUS_ALLOWED_HOSTS` задан, если Ollama не на localhost;
- [ ] включён ежедневный бэкап и проверено восстановление;
- [ ] настроен мониторинг `/api/health` (200/503);
- [ ] логи хранятся ограниченное время, доступ к ним — только у администратора;
- [ ] определены правила удаления телеметрии и ушедших пользователей;
- [ ] при публичном доступе проведён внешний пентест (MFA, CSRF, rate-limit — в первую очередь).
