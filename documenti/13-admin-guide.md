## Доступ в админку

- Адрес: `/admin.html` (иконка `⚙` в топбаре, пункт «Админ-панель» в палитре `Ctrl+K`).
- Доступ — только роль сайта `admin`. Проверка двойная: на клиенте (`admin.js`:
  `if (data.user.role !== 'admin') location.href = '/'`) и на сервере
  (`requireSelfAdmin` → `role !== 'admin'` → `403`).
- Вкладки «Darcus», «Реклама», «Подписки», «Телеметрия», «Баги», «Голос» показываются
  только администратору (в HTML они скрыты, `admin.js` включает их при `role === 'admin'`).
- Открывается на вкладке **«Обзор»**.

⚠️ В подсказках на вкладках Darcus/Телеметрия написано «доступно только пользователю
с логином `admin`» — это устаревший текст. Фактически доступ определяется ролью
`admin`, логин может быть любым.

## Обзор

Вкладка `dashboard` (`GET /api/admin/dashboard`), обновляется при открытии.

| Блок | Что показывает |
|---|---|
| Состояние | окружение (`production`/`development`), версия Node, uptime |
| Хранилище | логический размер SQLite, число пользователей, проектов, записей журнала, событий телеметрии, уведомлений, документов, сессий, версия схемы, дата миграции JSON |
| Размеры на диске | БД, лог, `embeddings.json`, `ocr-cache.json`, вложения, проекты, бэкапы |
| Ollama | доступность, URL, ошибка (если есть), список ролей моделей с флагом `installed` |
| Бэкапы | последние 10 каталогов: имя, размер, дата, «с проектами» |

Кнопки:

| Кнопка | Что делает |
|---|---|
| Обновить | повторный `GET /api/admin/dashboard` |
| Создать бэкап | `POST /api/admin/backup` → запуск `scripts/backup.js`; по умолчанию **без** файлов проектов (`--no-projects`), таймаут 180 с |
| Экспорт | `GET /api/admin/export` — JSON-снимок пользователей/проектов/документов |
| Импорт | выбор файла → двухшаговое подтверждение → `POST /api/admin/import` |

Проверка моделей: зелёная метка — модель найдена в `ollama list` (сравнение по имени,
`name:latest` и префиксу `name:`), серая — не найдена. Обязательна только чат-модель.

## Пользователи

Вкладка `users`.

Создание:

| Поле | Ограничения |
|---|---|
| Логин | 3–64, `a-z A-Z 0-9 . _ - @` |
| Пароль | минимум 8 символов, строчная+заглавная+цифра |
| Роль | «Участник» (`member`) или «Администратор» (`admin`) |

⚠️ В форме стоит `minlength="6"`, а сервер требует 8 — введите пароль от 8 символов,
иначе получите ошибку сервера.

Список: поиск по логину/роли, количество, таблица (логин, роль, дата создания).
Действия в строке: сменить роль, сбросить пароль, удалить.

Инварианты (сервер):

- нельзя снять роль с последнего администратора;
- нельзя удалить последнего администратора;
- нельзя удалить себя (через `DELETE /api/users/:id`);
- пользователи, созданные здесь, не требуют инвайта;
- хеши паролей никогда не отдаются (`GET /api/users` исключает `password`).

Ответы: `409 Логин занят`, `400` с текстом политики пароля, `404 not found`.

## Приглашения

Вкладка `invites` (`/api/invites*`).

| Блок | Действие |
|---|---|
| Сгенерировать коды | количество 1–50, заметка до 200 символов; код — 10 символов из алфавита `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (без похожих `I/O/0/1`) |
| Добавить вручную | код 4–64, `A–Z 0–9 - _`, автоматически в верхний регистр |
| Все коды | поиск по коду/заметке/логину, фильтр «Свободные/Использованные», удаление |

Код одноразовый: после регистрации заполняются `usedBy` и `usedAt`, повторная попытка
даёт `409 Код уже использован`. Удаление кода не влияет на уже зарегистрированных.

## Наказания

Вкладка `punishments` (`/api/punishments*`).

| Поле | Значения |
|---|---|
| Пользователь | логин (нельзя наказать себя) |
| Тип | `ban` (бан) или `mute` (мьют) |
| Длительность | `forever` или миллисекунды (в UI — пресеты) |
| Причина | до 500 символов |

Поведение:

- **бан** — при следующем запросе сессия уничтожается, SSE-потоки получают `banned`
  и закрываются; вход возвращает `403 banned` с причиной и сроком;
- **мьют** — запрещает отправку в общий чат (`403 muted`), чтение и проектные чаты
  остаются доступны;
- активные наказания проверяются по `until` (пусто = навсегда);
- снятие — `DELETE /api/punishments/:id`;
- все действия пишутся в журнал (`punish-ban`, `punish-mute`, `unpunish`).

Наказать можно также из меню проекта → «Участники» (кнопка у пользователя).

## Журнал

Вкладка `changes` (`GET /api/changes`, `POST /api/revert/:id`).

Фильтры:

- период: 1 / 7 / 30 дней / всё время (`days`);
- файл: путь (`file`);
- пагинация: `limit` до 500, `offset`.

Что видно: время, пользователь, действие, файл, проект, детали. Для `full=1` —
ещё `before`/`after` (в UI — diff по кнопке).

Откат:

- доступен только администратору;
- `edit` — восстанавливает `before`;
- `create`/`upload`/`mkdir` — удаляет созданное (папки — рекурсивно);
- `delete` — восстанавливает файл, **если** он не был удалён в корзину и не был папкой;
- `move`/`rename` — возвращает на прежний путь;
- запрещён, если содержимое отредактировано (секрет/обрезка) или запись уже откатана;
- после отката сбрасывается кэш эмбеддингов по затронутым путям;
- запись помечается `reverted`, `revertedAt`, `revertedBy`, добавляется запись `revert`.

## Настройки

Вкладка `settings` (`GET/PATCH /api/settings`).

| Настройка | Значения | Действие |
|---|---|---|
| Лимит загрузки для участников | 1…100 000 МБ | применяется к `POST /api/upload`; у администраторов лимита нет |
| Общий чат | `everyone` / `admins_only` | `admins_only` блокирует отправку всем, кроме админов (проектные чаты и поддержка не затрагиваются) |

Для администратора `GET /api/settings` возвращает `uploadLimitMB: null` — это признак
«лимит не применяется», а не ошибка.

## Телеметрия

Вкладка `telemetry` (`/api/telemetry*`).

- Слева — список пользователей: логин, число событий, последняя активность и последняя
  запись `client-info` (`lastClient`), если она есть.
- Справа — события выбранного пользователя (тип, время, детали).
- Кнопки: «Обновить», поиск по логину, «Очистить» (для выбранного пользователя).

Типы событий: `login`, `logout`, `register`, `request` (HTTP-запрос с методом, путём,
статусом, длительностью, IP, UA), `client-info` (экран, viewport, язык, TZ, платформа,
ядра, память, touch, сеть, DNT, PWA-режим), `password-change`, `self-delete`,
`chat-message-delete`, `attach-upload`, `attach-access-denied`.

Ограничения и приватность:

- до 2 000 событий на пользователя (старые вытесняются);
- данные содержат IP и User-Agent — обращайтесь как с персональными данными;
- очистка необратима;
- события `request` пишутся на каждый запрос (кроме статики и 304), поэтому объём растёт
  быстро — чистите периодически.

## Вкладка Darcus

`GET/PATCH /api/darcus/config`, `POST /api/darcus/test`, `GET /api/darcus/models`,
`POST /api/darcus/reindex`.

Форма «Настройки Darcus (Ollama)»:

| Поле | Смысл | Диапазон в UI |
|---|---|---|
| URL Ollama | адрес API | `http://localhost:11434` |
| Модель чата | `chatModel` | из `datalist` (загружается кнопкой) |
| Vision/OCR | `visionModel` | обязательно vision-модель |
| Embeddings | `embedModel` | `nomic-embed-text` |
| Reranker | `rerankModel` | пусто = лексический реранк |
| num_ctx | окно контекста | 512…32 768 |
| temperature | креативность | 0…2 |
| Timeout | мс | 1 000…600 000 |

Кнопки:

| Кнопка | API | Что делает |
|---|---|---|
| Сохранить | `PATCH /api/darcus/config` | валидирует URL, сохраняет `ollama`/`prompts`/`search`/`ocr` |
| Проверить связь | `POST /api/darcus/test` | `ollamaPing`, возвращает список моделей |
| Загрузить модели | `GET /api/darcus/models` | заполняет `datalist` |
| Переиндексировать | `POST /api/darcus/reindex` | полный обход доступных проектов, до бесконечности чанков (может быть долго) |

«Промпты» — текстовые поля для `system`, `chat`, `rephrase`, `shorten`, `fix`,
`translate`, `summarize`, `generate_doc`, `ocr`, `vision`, `template_*`.
Подстановки перечислены подсказкой: `{username}` `{role}` `{project}` `{file}` `{date}`
`{time}` `{lang}` `{context}` `{query}` `{history}` `{text}` `{prompt}` `{template}`.

Практика:

- после смены `embedModel` — сразу «Переиндексировать»;
- после правки `vision`/`ocr` — проверьте на реальном скриншоте;
- если «Проверить связь» возвращает `ok:false`, Darcus работать не будет, остальное —
  будет;
- ошибки сохранения — `400 URL: …` (SSRF-валидация) или `403 forbidden`.

## Реклама

Вкладка `ads` (`/api/ads/*`).

Слоты (6): `topbar`, `sidebar-top`, `sidebar-bottom`, `chat-top`, `filebar`, `empty-viewer`.

| Действие | Как |
|---|---|
| Включить/выключить слот | переключатель; `PATCH /api/ads/slots` |
| Интервал ротации | секунды, минимум 3 |
| Загрузить картинку | PNG/JPG/GIF/WEBP/SVG до 5 МБ |
| «На все слоты» | `allSlots: true` — картинка дублируется во все включённые слоты |
| Включить/выключить картинку | `PATCH /api/ads/images/:id` |
| Удалить | `DELETE` (файл тоже удаляется) |

Распределение: картинки с `allSlots` попадают во все слоты, остальные раздаются
round-robin по включённым слотам. `GET /api/ads/serve` возвращает `{slots,images,distribution}`.

Ограничения:

- до 5 000 картинок (старые удаляются вместе с файлами);
- файлы лежат в `data/ads`;
- SVG отдаётся с закрытым CSP, но остаётся SVG — загружайте только доверенные файлы;
- показ рекламы в интерфейсе управляется ещё и профилем: чекбокс «отладочная реклама»
  (`localStorage showAds`).

## Подписки

Вкладка `subs` (`/api/subscriptions*`).

Подписка «Dark Army Intelligence» открывает: чат Darcus, rewrite/summarize,
генерацию документов, анализ изображений. Администратор сайта имеет доступ без подписки.

| Блок | Действие |
|---|---|
| Активные | таблица: логин, «до», кто выдал; отзыв |
| Выдать вручную | логин, дни (≥1, по умолчанию 30), заметка |
| Коды активации | генерация 1–50 кодов вида `DAI-XXXXXXXXXX` на N дней; таблица кодов со статусом; удаление |

Особенности:

- код одноразовый (`usedBy`/`usedAt`);
- активация продлевает срок до `now + days` (перезаписывает, не суммирует);
- отзыв подписки (`DELETE /api/subscriptions/:username`) сразу закрывает Darcus
  для пользователя;
- `GET /api/me/subscription` возвращает `forceAdmin: true` для логина `admin`
  (историческое поле; фактический доступ даёт роль).

## Баги

Вкладка `bugs` (`/api/bugs*`, `src/routes/bugs.js`).

Пользователь нажимает «БАГ» в топбаре, пишет описание (≥5 символов) и может приложить
скриншот (PNG/JPG/WEBP ≤3 МБ, из файла или `Ctrl+V`). Администраторам приходит уведомление
с ссылкой `admin:bugs`.

В админке:

| Действие | API | Детали |
|---|---|---|
| Список | `GET /api/bugs` | новые сверху, всего до 300; поля: пользователь, описание, страница, дата, флаг скриншота |
| Скриншот | `GET /api/bugs/:id/screenshot` | `no-store`, MIME из записи |
| Редактировать текст/страницу | `PATCH /api/bugs/:id` `{description,page}` | пустое описание запрещено |
| Заменить скриншот | `PATCH /api/bugs/:id` `{screenshot:"data:image/…"}` | старый файл удаляется, новый пишется как `<id>.<ext>` |
| Удалить | `DELETE /api/bugs/:id` | удаляет запись и файл, необратимо |

Данные: метаданные — документ `bugs` в SQLite, файлы — `data/bug-reports/<id>.<ext>`.
Лимит отправки — 6/мин на пользователя; размер списка — 300 (старые вытесняются).

Рекомендуемый порядок работы с багом:

1. воспроизвести и описать шаги;
2. исправить код;
3. прогнать `npm test` и `npm run check`;
4. проверить сценарий вручную;
5. только после этого удалить баг из списка (иначе потеряете скриншот и контекст).

Подробнее — `docs/AGENT_BUGS.md`.

## Голос

Вкладка `voice` (`GET/PATCH /api/admin/voice`, `POST /api/admin/voice/install`).

Статус: `whisper`, `tts`, доступность Silero (`sileroHealthy`), PID процесса.

### STT

| Поле | Значения |
|---|---|
| Движок | пусто (браузер/не настроен), `faster-whisper`, `whisper.cpp` |
| Модель faster-whisper | `base`, `small`, `medium`, … |
| Язык | `ru` |
| Кнопка «Установить Whisper (авто)» | выполняет `python -m pip install --upgrade faster-whisper`, прописывает `engine: faster-whisper`, `model: base`, `language: ru` |

### TTS

| Поле | Значения |
|---|---|
| TTS URL | `http://127.0.0.1:8765/tts` |
| Голос | `aidar`, `baya`, `kseniya`, `xenia`, `eugene` |
| Кнопка «Установить/запустить Silero» | проверяет `/health` на 8765 и при необходимости запускает Python-сервер; прописывает URL/голос/формат |

«Сохранить настройки» — `PATCH /api/admin/voice`; «лог» под формой показывает вывод
операций установки.

Важно:

- микрофон в браузере работает только по HTTPS/localhost; для LAN есть встроенный
  HTTPS-порт или системный диктофон (см. [02-installation.md](02-installation.md));
- первый синтез Silero грузит модель (может занять минуту);
- установка faster-whisper требует Python в PATH (или `PYTHON_BIN`);
- после установки проверьте `GET /api/darcus/capabilities` — там `stt`/`tts`/`ttsMode`.

## Экспорт, импорт, бэкап

### Бэкап

- Кнопка «Создать бэкап» → `scripts/backup.js --dest <BACKUP_DIR> --no-projects`
  (чтобы включить проекты, нужен вызов API с `{"projects":true}`; в UI кнопка без проектов).
- Ротация по `--keep` (по умолчанию 7).
- Результат — каталог `BACKUP_DIR/<ISO>/` c `dossier.db`, `data/`, `manifest.json`.
- Для ежедневного бэкапа — `deploy/install-backup-task.ps1` (Windows) или cron/timer
  ([10-deployment-ubuntu.md](10-deployment-ubuntu.md#бэкапы-по-расписанию)).

### Экспорт

`GET /api/admin/export` — JSON:

```json
{ "app":"darkarmy-dossier","version":1,"exportedAt":"…",
  "users":[…],"projects":[…],"documents":{…} }
```

Не содержит журнал, телеметрию, сессии, уведомления, файлы проектов и вложения.

### Импорт

`POST /api/admin/import` с `confirm:"REPLACE"` и `mode:"replace"|"merge"`.

- проверки: формат `app`, `version === 1`, наличие пользователей и хотя бы одного админа;
- `replace` очищает `users`, `projects`, `documents` перед записью;
- операция в одной транзакции;
- после импорта возможен выход из аккаунта (если вашего пользователя нет в снимке);
- перед импортом **обязательно** сделайте бэкап.

## Типовые операции

| Задача | Шаги |
|---|---|
| Добавить сотрудника | Приглашения → сгенерировать код → передать; или Пользователи → создать вручную |
| Дать доступ к проекту | Проект → Участники → добавить с ролью `member`/`editor` |
| Запретить писать в общий чат | Настройки → Общий чат → «Только администраторы» |
| Забанить спамера | Наказания → пользователь → тип `ban` → срок/навсегда → причина |
| Восстановить удалённый файл | Проект → Корзина → «Восстановить» (в течение 14 дней) |
| Откатить правку | Журнал → найти запись → «Откатить» (только admin) |
| Ускорить поиск | Darcus → «Переиндексировать» (после смены embedding-модели — обязательно) |
| Проверить, что всё живо | Обзор → статус БД/моделей/бэкапов; `GET /api/health` |
| Почистить телеметрию | Телеметрия → пользователь → «Очистить» |
| Выдать Darcus без оплаты | Подписки → выдать вручную на N дней |
