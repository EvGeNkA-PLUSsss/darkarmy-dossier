## Общее

**1. Что такое DarkArmy Dossier?**
Self-hosted система командной работы с файлами: проекты и роли, дерево файлов,
редактор Markdown с совместной правкой, чаты и тикеты, задачи/канбан, локальный
ИИ-ассистент Darcus, админ-панель. Данные — на вашем диске, ИИ — на вашей Ollama.

**2. Это облако или локальное приложение?**
Локальное. Метаданные — SQLite `data/dossier.db`, файлы — `PROJECTS_ROOT`,
ИИ — Ollama. В интернет ничего не уходит, кроме запросов Darcus к DuckDuckGo
и Википедии (можно отключить, поставив `webResults`/`wikiResults` в 0).

**3. Какая лицензия?**
AGPL-3.0-only. Если вы даёте доступ к изменённой версии по сети, исходники должны быть
доступны пользователям.

**4. Есть ли мобильное приложение?**
Есть PWA (устанавливается на Android/iOS/Windows) и Electron-обёртка. Готового APK
в репозитории нет — его можно собрать через Bubblewrap/TWA
([09-desktop-mobile-pwa.md](09-desktop-mobile-pwa.md)).

**5. Можно ли использовать без интернета?**
Да, полностью локально. Нужен интернет только для: скачивания npm-пакетов и моделей
Ollama/Silero при установке, и для веб-поиска Darcus (если включён).

## Установка и запуск

**6. Какая версия Node нужна?**
20+ по `engines`, рекомендуется **24 LTS** (на ней идёт CI). `node:sqlite` без флагов
доступен в актуальных 22/24.

**7. Как запустить на Windows?**
`npm install` → скопировать `.env.example` в `.env` → `node --env-file=.env server.js`.
Либо двойной клик по `start.bat` — он создаст `.env` со случайным секретом.

**8. Как поменять порт?**
`PORT=8080` в `.env` и перезапуск. Порт должен быть свободен; для LAN дополнительно
правило брандмауэра.

**9. Как открыть доступ из локальной сети?**
`BIND_HOST=0.0.0.0`, правило брандмауэра для TCP 7561 (профиль Private, ограничение
подсетью) и `http://<IP>:7561`. Помните: это HTTP без шифрования — только доверенная сеть.

**10. Почему на Linux не работает `PROJECTS_ROOT` по умолчанию?**
Значение по умолчанию — `F:/Проекты` (Windows-путь). На Linux задайте
`PROJECTS_ROOT=/srv/darkarmy-projects`.

**11. Где взять пароль администратора?**
При первом запуске он печатается **в консоль** (если не задан `ADMIN_PASSWORD`).
В лог-файл не пишется. После входа смените его в профиле.

**12. Забыл пароль администратора, что делать?**
Остановите сервер, сделайте бэкап `data/`, затем:

```bash
node -e "const s=require('./src/storage'),b=require('bcryptjs');s.init({dir:'./data'});const u=s.getUsers();const a=u.find(x=>x.username==='admin');a.password=b.hashSync('NewStrongPass123',10);s.replaceUsers(u);s.close()"
```

Запустите сервер и войдите с новым паролем. Скрипта сброса в комплекте нет ❌ —
это единственный штатный путь.

**13. Нужен ли Python?**
Только для голоса (Silero TTS и faster-whisper). Без него работают браузерный синтез
и Web Speech API.

**14. Нужна ли видеокарта?**
Нет. Ollama и faster-whisper работают на CPU; 3–4B модели будут медленнее, но рабочими.
Для комфорта — 8+ ГБ RAM.

## Доступ и безопасность

**15. Кто может создавать проекты?**
Любой авторизованный пользователь. Удалять проекты — только администратор.

**16. Как добавить человека без приглашения?**
Админка → Пользователи → «Создать пользователя» (логин, пароль, роль). Инвайт нужен
только для самостоятельной регистрации.

**17. Чем отличаются роли `member` / `editor` / `creator`?**
`member` — чтение, `editor` — чтение и правка файлов, `creator` — плюс управление
участниками и настройками проекта. Роль сайта `admin` даёт доступ ко всем проектам
и админке.

**18. Как выгнать пользователя из проекта?**
Проект → Участники → удалить (создатель или админ). Создателя удалить нельзя.
Самому выйти из проекта нельзя ❌.

**19. Как забанить/замьютить?**
Админка → Наказания (или меню проекта → Участники). Бан рвёт сессии и SSE, мьют
запрещает писать в общий чат.

**20. Есть ли двухфакторная аутентификация?**
Нет ❌. Защита: сильный пароль, ограничение доступа по сети, HTTPS, лимит попыток входа.

**21. Безопасно ли публиковать в интернет?**
Да, при соблюдении чек-листа: `NODE_ENV=production`, уникальный `SESSION_SECRET`,
`BIND_HOST=127.0.0.1` + HTTPS reverse proxy, `TRUST_PROXY=1`, сменённый пароль admin,
закрытые правами каталоги `data/`, включённые бэкапы. Полный список —
[08-security.md](08-security.md#чек-лист-безопасности).

## Файлы и данные

**22. Где лежат файлы проектов?**
В `PROJECTS_ROOT/<folder>/`, где `folder` — папка проекта (обычно UUID).
Проект «Основной» — `PROJECTS_ROOT/default/`.

**23. Где лежат пользователи и пароли?**
SQLite `data/dossier.db`, таблица `users`, поле `payload` (JSON с bcrypt-хешем).
Пароли в открытом виде не хранятся.

**24. Можно ли хранить файлы на сетевом диске?**
Технически да, но SQLite с WAL плохо работает на SMB/NFS — возможны блокировки
и повреждения. Держите `DATA_DIR` на локальном диске; `PROJECTS_ROOT` — можно сетевой,
но с осторожностью.

**25. Как забэкапить всё?**
`npm run backup` (SQLite через backup API + `data/` + `PROJECTS_ROOT` в `BACKUP_DIR`,
ротация). Расписание — Планировщик Windows или cron/systemd timer.

**26. Достаточно ли экспорта из админки как бэкапа?**
Нет. Экспорт содержит только пользователей, проекты и JSON-документы. Без `dossier.db`,
файлов проектов, вложений и кэшей это не восстановление.

**27. Что такое `.trash`?**
Корзина проекта. Удалённые файлы живут там 14 дней, затем чистятся. Восстановление —
из интерфейса («Корзина»), не вручную.

**28. Как перенести инсталляцию на другой сервер?**
Остановить сервис → скопировать `data/` и `PROJECTS_ROOT` (или развернуть бэкап) →
поправить `.env` (пути, `SESSION_SECRET` можно оставить) → запустить → проверить
`/api/health`. Если менялся `SESSION_SECRET`, все сессии станут недействительны.

## Darcus и ИИ

**29. Почему Darcus не отвечает?**
Ollama не запущена, модели не скачаны или URL неверный. Проверка: админка → Darcus →
«Проверить связь»; `curl http://localhost:11434/api/tags`.

**30. Какие модели нужны?**
Обязательна чат-модель (`gemma4:e4b` в репозитории). Желательны `qwen2.5vl:3b` (vision/OCR)
и `nomic-embed-text` (семантика). Реранкер опционален.

**31. Можно ли подключить OpenAI/Anthropic вместо Ollama?**
Нет ❌. Клиент написан под Ollama HTTP API. Теоретически можно поднять совместимый
прокси и указать его URL, но это не поддерживается.

**32. Что значит «контекст израсходован на 85%»?**
Оценка занятого окна `numCtx` (символы / 3.2). При 90 %+ модель может терять начало
диалога — начните новый чат или уменьшите вложения.

**33. Почему Darcus создаёт файл, но не показывает текст в чате?**
Так задумано: для объёмных текстов он пишет файл через ACTION и даёт короткое
подтверждение. Это экономит контекст и не дублирует содержимое.

**34. Почему `generate_doc` из чата не срабатывает?**
Клиентский парсер (`AI_ACTION_TYPES`) его поддерживает, а дефолтный промпт `darcus.js`
описывает. Но в поставляемом `data/ai-config.json` текст `system` перечисляет только
`create/edit/mkdir/delete/move/rename` — модель может просто не предложить это действие.
Добавьте `generate_doc` в промпт `system` (админка → Darcus → Промпты) либо используйте
кнопку «Darcus — создать» / `POST /api/darcus/generate-doc`. Также проверьте подписку
и обновите страницу (`Ctrl+F5`), если `app.js` закэширован.

**35. Нужна ли подписка для Darcus?**
Для чата, rewrite, summarize, generate-doc и анализа изображений — да (админ сайта
без неё). TTS/STT и стили — без подписки.

**36. Где менять характер ответов?**
Админка → Darcus → «Промпты» (`system`, `chat`, …) и стиль в панели Darcus
(«По умолчанию/Формально/Дружелюбно/Тезисно/Для кода»).

## Голос

**37. Почему не работает микрофон?**
Браузер даёт `getUserMedia` только на `localhost` или HTTPS. По HTTP в LAN:
откройте встроенный HTTPS-порт (`HTTPS_PORT`) либо включите серверный Whisper —
тогда кнопка микрофона откроет системный диктофон телефона.

**38. Как сделать «нормальный» голос?**
Установить Silero TTS v5.6 RU (`scripts/silero_tts_server.py`, порт 8765) и прописать
`TTS_URL`/голос. Без него используется браузерный синтез.

**39. Распознавание выдаёт «кракозябры».**
Обновите версию: скрипт выводит UTF-8 (`PYTHONIOENCODING`, `PYTHONUTF8`,
`sys.stdout.buffer`). Проверьте вручную:
`python scripts/faster_whisper_stt.py base test.webm ru`.

**40. Почему ответы в голосовом режиме короткие?**
Так задумано: системный промпт требует 1–3 предложения без списков и кода, чтобы
озвучка не длилась минутами. Отключите голосовой режим — ответы станут обычными.

## Приложение и мобильные

**41. PWA не устанавливается.**
Нужен HTTPS (или localhost) и корректный `manifest.webmanifest`. На iOS кнопки нет —
только «Поделиться» → «На экран Домой».

**42. Работает ли приложение офлайн?**
Да, если включить «Офлайн-режим» в профиле: скачиваются проекты, деревья, задачи и файлы.
Без интернета доступен только просмотр — редактирование отключается. Нужен HTTPS или localhost.

**43. Чем Electron-версия отличается от PWA?**
Electron — отдельное окно с иконкой, требует установленного Node. PWA ставится из браузера
и не требует Node, но живёт в браузерной песочнице. Для Windows есть готовый
`release/DarkArmyDossier.exe` — лаунчер, который сам поднимает сервер и открывает окно.

**44. Можно ли собрать APK?**
Да. В репозитории уже есть `release/DarkArmyDossier.apk` (WebView-клиент, debug-подпись)
и исходники `android/` для пересборки. Для TWA/Google Play нужны HTTPS-домен, keystore и
`/.well-known/assetlinks.json`.

## Совместная работа

**45. Сколько человек могут править один файл?**
Ограничения на число участников сессии нет, но одновременно комфортно 2–3:
конфликты решаются «последний победил», без слияния.

**46. Что происходит при закрытии вкладки без сохранения?**
Сервер записывает актуальный текст (flush при выходе последнего участника), поэтому
набранное не теряется. Но явное `Ctrl+S` надёжнее.

**47. Почему правки не появляются у коллеги?**
Проверьте: тот же проект, файл открыт в редакторе, SSE-соединение активно
(DevTools → Network → `events`), нет `410 session ended`.

**48. Два устройства одного аккаунта синхронизируются?**
Да, они различаются по `clientId` (в `sessionStorage` вкладки) и получают правки
друг друга.

## Обслуживание

**49. Как обновить версию?**
Бэкап → `git pull` → `npm ci --omit=dev` → `npm run check` → перезапуск
(`systemctl restart` / `pm2 restart`) → проверка `/api/health`. Миграции БД выполняются
автоматически при старте.

**50. Куда пишутся логи?**
`data/log.txt` (JSON, ротация 10 МБ × 5), `journalctl -u darkarmy-dossier` (systemd),
`data/pm2-*.log` (PM2). Access-log не пишет статику и 304.

**51. Как почистить старые данные?**
Журнал ограничен 5 000 записями, телеметрия — 2 000 на пользователя, уведомления — 200,
чаты — 1 000/3 000 сообщений, корзина — 14 дней. Вручную: админка → Телеметрия →
«Очистить»; журнал/уведомления массовой очистки в UI не имеют ❌.

**52. Что делать, если БД «locked»?**
Убедиться, что запущен **один** процесс на `DATA_DIR`; не копировать `dossier.db`
вручную при работающем сервере; перенести `data/` на локальный диск. См.
[11-troubleshooting.md](11-troubleshooting.md#sqlite-и-database-is-locked).

**53. Где сообщить о баге?**
Кнопка «БАГ» в шапке приложения: описание + скриншот (до 3 МБ). Администратор увидит
запись в Админка → Баги.

**54. Можно ли запустить несколько экземпляров для масштабирования?**
Нет ❌: SSE-клиенты и сессии редактирования в памяти процесса, SQLite-файл один.
Нужен рефакторинг под Redis/Postgres.
