## Вход и регистрация

**Вход** — `/login.html`: логин и пароль. После успеха открывается основное приложение `/`.

**Регистрация** — `/register.html`: логин (3–64 символа: буквы, цифры, `. _ - @`), пароль
и **код приглашения**. Без кода зарегистрироваться нельзя; коды выдаёт администратор
(Админка → Приглашения).

Требования к паролю (проверяются и при регистрации, и при смене):

- минимум 8 символов;
- есть строчная и заглавная буква, есть цифра;
- не одна и та же буква/цифра;
- не последовательность (`12345678`, `qwerty…`);
- не из списка частых паролей;
- не содержит логин.

Если вас забанили, при входе показывается причина и срок; сессия уничтожается.

## Проекты

**Выбор проекта** — выпадающий список в сайдбаре. Приложение запоминает последний проект
в `localStorage` (`lastProject`) и последний файл в каждом проекте (`lastFileByProject`).

**Создать проект**: «…» → «Новый проект» (или меню проекта → создать) → имя (до 100 символов).
Создатель получает роль `creator`; на диске создаётся папка `PROJECTS_ROOT/<uuid>`.

**Меню проекта** (кнопка с названием проекта) — три вкладки:

| Вкладка | Что можно |
|---|---|
| Участники | список участников и их роли; добавить пользователя с ролью `member`/`editor`/`creator`; сменить роль; удалить участника; наказать (бан/мьют) — администратор |
| Настройки | переименовать проект (создатель или админ); удалить проект — **только администратор** |
| Последние действия | журнал изменений проекта (только создатель/админ), переход к файлам |

Ограничения:

- Создателя проекта нельзя понизить в роли или удалить из участников.
- Выйти из проекта самостоятельно нельзя ❌ — удаляет создатель или администратор.
- Проект «Основной» (`id: default`) создаётся автоматически при первом запуске.

## Дерево файлов и папок

- Скрытые элементы (имена, начинающиеся с `.`) и служебная папка `.trash` не показываются.
- Папки раскрываются кликом; рядом с именем — иконки и, для избранного, звёздочка.
- Двойной клик по файлу открывает его; одиночный — выделяет.
- **Множественный выбор**: `Ctrl+клик` (точечно), `Shift+клик` (диапазон), стрелки + `Ctrl`.
  `Delete`/`Backspace` удаляет выбранное (с подтверждением).
- **Перетаскивание**: файл/папку можно перетащить в другую папку того же проекта
  или на другой проект в выпадающем списке (откроется модалка «Переместить в…»).
- **Контекстное меню** (правый клик; на мобильном — долгое нажатие):

| Действие | Файл | Папка | Корень |
|---|---|---|---|
| Открыть | ✓ | ✓ | — |
| Редактировать (только `.md`) | ✓ | — | — |
| Скачать | ✓ | — | — |
| Поделиться… | ✓ | — | — |
| В избранное / Убрать | ✓ | — | — |
| Теги… (до 8 тегов) | ✓ | — | — |
| Запрос на изменение | ✓ | — | — |
| Пожаловаться | ✓ | — | — |
| Переместить в… | ✓ | ✓ | — |
| Переименовать | ✓ | ✓ | — |
| Удалить (в корзину) | ✓ | ✓ | — |
| Новый файл / Новая папка / Загрузить | — | ✓ | ✓ |

Удаление отправляет объект в `.trash` проекта с метаданными (`trash.json`/документ `trash`),
откуда его можно восстановить или удалить окончательно. Срок хранения — 14 дней, затем
очистка при следующем обращении к корзине.

## Загрузка файлов

Три способа:

1. Кнопка **«Загрузить»** в сайдбаре.
2. Контекстное меню → «Загрузить файл».
3. **Drag & drop** файла в область просмотра (работает и на пустом состоянии дерева).

Ограничения:

| Параметр | Значение |
|---|---|
| Лимит для участника | 50 МБ по умолчанию, меняется в Админка → Настройки |
| Лимит для администратора | 100 000 МБ (жёсткий предел multer — 2 ГБ) |
| Вложения в чат | 25 МБ, исполняемые расширения запрещены |
| Частота | не более 30 загрузок в минуту |

При совпадении имён сервер добавляет суффикс: `отчёт (1).docx`. Имена с кириллицей,
пробелами и `%` поддерживаются. Загрузка пишется в журнал (`action: "upload"`),
для изображений в фоне запускается OCR (если включён `ocr.autoOnUpload`), затем —
индексация эмбеддингов.

## Просмотр файлов

| Формат | Как отображается |
|---|---|
| `.md`, `.markdown` | отрендеренный Markdown (таблицы, код, ссылки, изображения) |
| изображения (`png/jpg/jpeg/gif/webp/bmp/ico`) | инлайн, клик открывает lightbox |
| `.pdf` | встроенный просмотрщик браузера |
| `.docx` | конвертация mammoth → HTML |
| `.xlsx/.xls/.ods` | таблица (SheetJS), листы переключаются |
| текст/код (`txt/js/json/css/html/…`) | как текст (HTML не исполняется) |
| прочее | скачивание (attachment) |

Если файл не найден (удалён/переименован), показывается сообщение «Файл не найден»
и предложение обновить дерево — вместо пустого экрана.

Кнопки filebar:

| Кнопка | Что делает |
|---|---|
| История | список версий и unified-diff |
| Запрос | отправить администратору запрос на изменение файла |
| Печать | печать текущего файла (для PDF/Office — встроенная печать, может быть пустой) |
| Жалоба | пожаловаться на файл (причина обязательна) |
| OCR | показать/скрыть распознанный текст изображения (если он есть в кэше) |
| Кратко | AI-суммаризация: TL;DR, тезисы, сущности (кэш 24 ч по SHA-1) |
| Ред. | открыть inline-редактор (только `.md` и при праве редактирования) |

## Редактор Markdown

Два варианта, оба работают с одним и тем же серверным механизмом сохранения:

### Inline-редактор (основной)

- Открывается кнопкой **«Ред.»** прямо над документом; область просмотра скрывается.
- Слева — текст, справа — живое превью (на мобильном можно отключить превью кнопкой «глаз»).
- В filebar появляются **«Сохранить»** и **«✕»** (закрыть без сохранения).
- Автосохранение черновика в `localStorage` (ключ `da_drafts`, `projectId::path`) —
  черновик восстанавливается после перезагрузки страницы.
- Сохранение — `Ctrl+S` или кнопка; черновик удаляется **только после успешного сохранения**.
- Повторное нажатие «Ред.» по тому же файлу не перечитывает файл с сервера — набранный
  текст не теряется.

### Модальный редактор

- Открывается из контекстного меню файла → «Редактировать».
- Полноэкранное окно с тулбаром и превью.
- Кнопки «Сохранить»/«Отмена»; закрытие по `Esc` эквивалентно «Отмене».
- Использует тот же `/api/edit/*`, поэтому участники обеих форм видят друг друга
  в счётчике «редактируют».

### Тулбар и Markdown

| Кнопка | Вставка |
|---|---|
| **B** | `**текст**` |
| *I* | `*текст*` |
| H1/H2/H3 | `#`, `##`, `###` |
| список | `- пункт` |
| нумерованный | `1. пункт` |
| цитата | `> текст` |
| код | блок ``` |
| таблица | заготовка таблицы 2×2 |
| ссылка | `[текст](url)` |
| изображение | загрузка файла в проект + вставка `![](...)` |
| скрепка | загрузка любого файла + вставка `[...](...)` |
| AI-кнопки | перефразировать / сократить / исправить / перевести (через Darcus) |

Поддерживается подсветка синтаксиса в блоках кода, кликабельные ссылки, относительные
ссылки на файлы проекта (преобразуются в `/files/<projectId>/…`), просмотр изображений
по клику. HTML в Markdown санитизируется (DOMPurify, локальная копия в `public/vendor`).

### Совместное редактирование

- Над редактором отображается «редактируют: логин1, логин2 (N устройств)».
- Правки других участников приходят по SSE и применяются к тексту автоматически
  (с сохранением позиции курсора, насколько это возможно).
- Одно и то же лицо может открыть файл на нескольких устройствах — они синхронизируются
  между собой (различаются по `clientId` в `sessionStorage`).
- Конфликты решаются по принципу **последний победил**; отдельных веток и merge нет.
- Подробности и ограничения — [07-collaboration.md](07-collaboration.md).

## История версий и diff

Кнопка **«История»** в filebar:

1. Открывается список версий файла (дата, автор, действие), пагинация по 50.
2. Клик по версии — unified-diff «до/после» с подсветкой `+`/`−` и статистикой.
3. Кнопка скачивания сохраняет выбранную сторону (`before` или `after`) как `*.txt`.

Что попадает в историю: создание, правка, загрузка, удаление, перемещение, переименование,
восстановление из корзины, действия Darcus. Для секретных файлов (`.env`, `*.pem`, `*.key`,
`*secret*`, `*password*` и т.п.) содержимое заменяется на `[REDACTED: sensitive file]`,
а для больших файлов обрезается после 32 КБ (`[...truncated]`) — откат таких записей
недоступен.

Откат версии выполняет **администратор** (`POST /api/revert/:id`):
`edit` — восстанавливает `before`; `create/upload/mkdir` — удаляет созданное;
`delete` — возвращает файл (кроме папок и удалений в корзину); `move/rename` — возвращает
на прежний путь.

## Поиск

Открывается кнопкой `🔍`, `Ctrl+K` или `Ctrl+Shift+F`.

Секции результата:

| Секция | Что ищет | Переход |
|---|---|---|
| Проекты | по названию | открывает проект |
| Файлы | имя, содержимое, распознанный текст изображений + семантика | открывает файл |
| Сообщения | общий чат и чаты доступных проектов | открывает чат и сообщение |
| Задачи | текст задач в доступных проектах | открывает доску задач |
| Люди | логины (админ — все, остальные — участники своих проектов) | упоминание/профиль |

Особенности:

- Минимум 2 символа; иначе пустой результат.
- Файловый поиск — гибридный: keyword-совпадение даёт 0.5–1.0, семантика — 0–1,
  при совпадении обоих добавляется 0.15. Сортировка по итоговому скору.
- Если embedding-модель недоступна, поиск деградирует до keyword без ошибок.
- Учитываются права: файлы и сообщения недоступных проектов не показываются.
- Лимиты: `/api/search` — 30 запросов/мин, `/api/search` по проекту — до 100 результатов,
  `/api/search-all` — до 150 результатов.

## Чаты

Панель чата открывается кнопкой в сайдбаре; четыре вкладки:

### Общий чат
- Все авторизованные (если админ не включил режим «только администраторы»).
- Хранится последние 1 000 сообщений; в интерфейсе показываются последние 300.
- Упоминания `@логин` создают уведомление участнику (до 5 адресатов).
- Своё сообщение можно удалить (у админа — любое); удаление синхронизируется по SSE.
- Мьют запрещает отправку в общий чат (`403 muted`).

### Чат проекта
- Доступен участникам проекта; сообщения и задачи проекта хранятся вместе.
- Последние 3 000 сообщений; показываются 300.
- Удалять сообщения может автор, создатель проекта и администратор.
- Вложения — до 10 на сообщение.

### Поддержка (тикеты)
- Один открытый тикет на пользователя; повторное создание вернёт `409` с `ticketId`.
- Статусы: `open` → `in_progress` (админ «принял») → `closed`.
- Системные сообщения о принятии/закрытии видны обеим сторонам.
- Ответы в закрытый тикет запрещены.

### Darcus
См. ниже.

Вложения в сообщениях: изображения показываются превью, остальные — карточкой с именем
и размером; клик по изображению открывает lightbox, правый клик по вложению — «Скачать»
и (если есть права) «Добавить в текущий проект».

## Задачи и канбан

Задачи живут в чате проекта (вкладка «Проект») и на доске.

- В чате проекта есть компактный список задач с чекбоксом и полем добавления.
- Кнопка «Доска задач» открывает модалку с тремя колонками: **К выполнению** (`todo`),
  **В работе** (`doing`), **Готово** (`done`).
- Перетаскивание карточки между колонками меняет статус и порядок (`order`).
- У задачи есть: текст (до 500 символов), исполнитель, приоритет (`low/normal/high`),
  срок (`YYYY-MM-DD`), автор, дата создания, кто и когда закрыл.
- Удалять задачу может автор, создатель проекта, администратор.
- Изменения приходят всем участникам проекта событием `project-task`.

Ограничения: подзадач, комментариев к задаче, вложений и повторяющихся задач нет ❌.
Задачи не синхронизируются с внешними трекерами.

## Darcus: чат с ИИ

Вкладка **Darcus** в панели чата.

### Что умеет
- отвечать по контексту файлов доступных проектов (RAG: keyword + эмбеддинги + реранк);
- искать в интернете (DuckDuckGo HTML) и Википедии, показывать источники;
- читать приложенные файлы и **изображения** (OCR + описание);
- создавать/изменять/удалять/перемещать/переименовывать файлы и папки (ACTION);
- генерировать большие документы отдельной кнопкой «Darcus — создать»;
- суммаризировать открытый документ (кнопка «Кратко»);
- озвучивать ответы и принимать голосовой ввод.

### Элементы панели

| Элемент | Назначение |
|---|---|
| Заголовок чата | открыть список чатов; текущий чат можно переименовать |
| `+` | новый чат (пустой не дублируется — вернётся существующий) |
| 🗑 | удалить текущий чат; в списке — «Удалить все чаты» |
| 🔈 «Голос» | голосовой режим: краткие ответы + озвучка + распознавание |
| «⚡ Авто» | применять действия Darcus без подтверждения |
| ✈ (рядом с «Голос») | авто-отправка распознанной речи (включена по умолчанию) |
| Селект стиля | «По умолчанию / Формально / Дружелюбно / Тезисно / Для кода» |
| «Стоп» | прервать генерацию (AbortController) |
| «Вниз» | прокрутить к последнему сообщению |
| Плашка контекста | «Контекст: N% (использовано X из Y токенов)» |
| «Активировать» | ввод кода подписки, если Darcus недоступен |

### Подписка

Чат Darcus, rewrite/summarize, генерация документов и анализ изображений требуют подписки
«Dark Army Intelligence» (администратор сайта имеет доступ без подписки). TTS/STT и стили
доступны всем авторизованным. Без подписки сервер отвечает `403 {"error":"subscription-required"}`,
а в панели показывается форма активации кода.

### Ограничения запроса

| Параметр | Лимит |
|---|---|
| Длина запроса | 8 000 символов |
| История | 12 последних сообщений, каждое до 8 000 символов |
| Файлы | 6 на сообщение, до 4 МБ каждый (изображения ~12 МБ в base64) |
| Частота | 20 запросов Darcus в минуту |
| Таймаут Ollama | 180 с (настраивается) |

## Плашки действий Darcus

Когда модель просит изменить файл, в ответе появляется ACTION-блок, который **не показывается
как сырой JSON**. Вместо него:

1. Если включён «⚡ Авто» — действие выполняется сразу.
2. Иначе появляется диалог подтверждения: тип действия, путь и первые 400 символов
   содержимого.
3. После выполнения в чате появляется зелёная плашка:
   `✅ Darcus создал файл: docs/guide.md` — она **кликабельна** и открывает результат.
4. При ошибке — красная плашка `⚠️ Darcus не выполнил действие: <причина>`.
5. При отмене — плашки нет, действие не выполнено.

Поддерживаемые действия: `create`, `edit`, `mkdir`, `delete`, `move`, `rename`,
`generate_doc`. Путь всегда относительный от корня проекта; сервер дополнительно
проверяет права (`projectGuard('edit')`) и безопасность пути (`safeJoin`).

`generate_doc` используется для больших документов (реферат, статья, документация):
Darcus возвращает только путь и короткое описание, а сервер генерирует полный текст
через `POST /api/darcus/generate-doc`. Если модель забыла ACTION, клиент сам
страхует создание и показывает плашку только после реального результата.

## Голосовой режим

Кнопка «Голос» (динамик) в шапке Darcus.

| Что происходит | Детали |
|---|---|
| Ответы озвучиваются | серверный TTS (Silero) → Web Audio; если серверный TTS не настроен — браузерный `speechSynthesis` с русским голосом |
| Ответы становятся краткими | системный промпт требует 1–3 предложения, без списков и кода |
| Распознанная речь вставляется в поле | при включённой авто-отправке сообщение уходит сразу |
| Авто-отправка | включена по умолчанию; кнопка ✈ отключает её, тогда текст остаётся для проверки |

Микрофон:

- `localhost`/`127.0.0.1` — работает всегда;
- HTTPS-адрес (`https://…:7562` или домен) — работает;
- **HTTP в локальной сети** — `getUserMedia` недоступен; есть два пути:
  1. открыть встроенный HTTPS-порт;
  2. если серверный Whisper включён, кнопка микрофона открывает **системный диктофон**
     телефона (`<input capture="microphone">`), запись уходит на `/api/darcus/transcribe`.

Движки распознавания (в порядке выбора):

1. `faster-whisper` (Python, локально) — если включён в админке;
2. `whisper.cpp` — если заданы `WHISPER_BIN` и `WHISPER_MODEL`;
3. Web Speech API (Chrome/Edge) — если ничего не настроено.

Проверить, что доступно: `GET /api/darcus/capabilities` →
`{"stt":true,"sttEngine":"faster-whisper","tts":true,"ttsMode":"server","lang":"ru"}`.

## Контекст и стили ответа

### Индикатор контекста

После каждого ответа сервер считает примерный объём промпта
(`символы / 3.2` для русского) и отдаёт `{used, limit, percent, remaining, nearLimit}`.
В панели отображается полоса и текст; при `percent ≥ 90` появляется предупреждение
`nearLimit` — модель может начать «терять» начало диалога. Рекомендуется начать новый чат.

Бюджет промпта ограничен `max(6000, numCtx × 2)` символов; контекст/история/вложения
делят его как 45 % / 25 % / 30 % с пометкой «сокращено из-за лимита контекста».

### Стили

| Стиль | Эффект |
|---|---|
| По умолчанию | без добавок |
| Формально | деловой язык, без сленга и эмодзи |
| Дружелюбно | тёплый тон, уместные эмодзи |
| Тезисно | только ключевые пункты |
| Для кода | технические примеры кодом |

Стиль применяется суффиксом к системному промпту и хранится в `localStorage` (`darcusStyle`).

### Источники

Под ответом показываются:
- **Файлы проекта** (до 8) — с переходом к файлу;
- **Интернет** (до 4 ссылок);
- **Википедия** (до 2 ссылок).

## Уведомления

Колокольчик `🔔` с числом непрочитанных. События:

- новое обращение в поддержку и ответы по нему;
- запрос на изменение файла и его закрытие;
- новая жалоба и результат рассмотрения;
- добавление в проект;
- упоминание `@логин` в общем или проектном чате;
- новый баг-репорт (администраторам).

Клик по уведомлению ведёт к объекту (тикет, файл, проект, чат). Есть «Прочитать все»
и «Очистить». Хранится до 200 уведомлений на пользователя; доставка — по SSE.

## Профиль, темы, подписка

Профиль (`👤`):

| Пункт | Что делает |
|---|---|
| Логин и роль | отображение |
| Подписка | статус, срок, кнопка «Активировать подписку» (код) |

| Отладочная реклама | чекбокс показа баннеров в интерфейсе (`localStorage showAds`) |

| Установить приложение | PWA-установка (если браузер поддерживает) |

Тема применяется мгновенно и хранится в SQLite (`users[].theme`), поэтому действует
на всех устройствах после входа.

## Кнопка «БАГ»

Кнопка **«БАГ»** в топбаре открывает модалку:

1. Описание (минимум 5 символов, до 4 000).
2. Страница подставляется автоматически (текущий URL).
3. Скриншот: выбрать файл PNG/JPG/WEBP до 3 МБ или **вставить из буфера** (`Ctrl+V`).

После отправки администраторы получают уведомление, а запись появляется в
**Админка → Баги**, где её можно отредактировать (текст и скриншот) или удалить.
Лимит — 6 багов в минуту.

## Корзина и share-ссылки

**Корзина** (`🗑`): список удалённых объектов текущего проекта с датой и автором.
Действия: «Восстановить» (на исходный путь; если там уже есть файл — `409`) и
«Удалить навсегда». Срок хранения — 14 дней.

**Share-ссылка**: контекстное меню файла → «Поделиться…»:

- срок действия: 1/7/30/365 дней или бессрочно;
- ссылка вида `<origin>/s/<token>`;
- кнопка «Копировать»;
- список активных ссылок с числом открытий и возможностью отозвать;
- ссылка работает без авторизации, но отдаёт файл по тем же правилам безопасности
  (HTML/JS как `text/plain`, SVG с закрытым CSP).

## Онбординг и справка

- При первом входе через ~1,2 с открывается **онбординг** («Добро пожаловать»):
  3 шага — создать проект и файл, спросить Darcus, работать вместе.
  Кнопки: «Начать работу», «Горячие клавиши», «Больше не показывать».
  Факт просмотра хранится в `localStorage` (`da_onboarding_seen`).
- **Справка** (`?` или `Ctrl+/`) содержит быстрые действия (создать файл/папку, спросить
  Darcus, загрузить), список горячих клавиш, кнопки «Установить приложение» и
  «Показать первые шаги».
- После обновления сервера вкладка сама перезагружается (проверка `/api/version`
  каждые 15 с и при возврате на вкладку) — чтобы не работать со старым `app.js`.

## Офлайн-режим (только просмотр)

1. Профиль → «Офлайн-режим».
2. Включите «Скачивать проекты для просмотра без интернета» — приложение скачает
   проекты, деревья файлов, задачи и файлы в Cache Storage.
3. Без интернета доступен только просмотр; кнопки создания/редактирования, задачи,
   чат и Darcus отключаются, чтобы не было конфликтов между участниками.
4. Значок статуса показывает число скачанных файлов и дату. «Скачать сейчас»
   обновляет данные, «Очистить» удаляет кэш.
5. Офлайн-кэш работает по HTTPS или на localhost; на обычном HTTP в LAN service worker
   недоступен.

## Микрофон на HTTP

Браузер запрещает `getUserMedia` вне secure context. При нажатии микрофона по HTTP
приложение предлагает открыть HTTPS-адрес (`https://хост:7562`) или записать голос
через системный диктофон (если включён серверный Whisper). Полноценное решение —
HTTPS-домен; см. [deploy/free-domain.md](../deploy/free-domain.md).

## Новые действия Darcus

Кроме создания/изменения файлов: `open` (открыть файл), `task` (создать задачу),
`search` (открыть поиск). Darcus также получает встроенные инструкции по приложению
(папка `ai-knowledge/`) и задачи текущего проекта.
