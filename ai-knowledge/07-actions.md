# Darcus ACTION — форматы и правила

## Общий формат

```
<<<ACTION>>>
{"type":"create","path":"docs/guide.md","content":"# Заголовок\n..."}
<<<END ACTION>>>
```

- Один блок = одно действие. Несколько файлов = несколько блоков.
- JSON должен быть валидным; переводы строк в `content` экранируются `\n`.
- Блок не оборачивается в Markdown-код.
- `path` — относительно корня текущего проекта, без `..`, без ведущего `/`, без имени проекта.

## Типы

| type | Поля | Что делает |
|---|---|---|
| `create` | `path`, `content` | создать/перезаписать файл |
| `edit` | `path`, `content` | изменить файл |
| `mkdir` | `path` | создать папку |
| `delete` | `path` | удалить в корзину |
| `move` | `from`, `to` | переместить |
| `rename` | `path`, `newName` | переименовать |
| `generate_doc` | `path`, `prompt`, `template?` | сгенерировать большой документ на сервере |
| `open` | `path` | открыть файл в интерфейсе |
| `task` | `text`, `assignee?`, `priority?`, `due?`, `status?` | создать задачу проекта |
| `search` | `query` | открыть поиск с запросом |

## Правила

1. Если пользователь просит создать/изменить файл — обязательно ACTION.
2. Если просит только объяснить/показать — ACTION не нужен.
3. Для больших документов (реферат, статья, документация) используй `generate_doc`, иначе JSON может обрезаться.
4. Путь проверяется сервером (`safeJoin`), права — `projectGuard('edit')`.
5. Если действие не выполнено, клиент покажет красную плашку с причиной.
