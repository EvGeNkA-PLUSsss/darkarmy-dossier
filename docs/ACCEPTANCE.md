## 4. Безопасность

- `script-src 'self'`, без inline-скриптов и CDN; библиотеки вендорены;
- allow-list отдачи файлов: `.shtml/.html/.svg/.svgz/.xht` отдаются как `text/plain`/attachment;
- IDOR-проверки: вложения (scope), история версий, share-ссылки, SSE — только участникам;
- rate-limit входа/поиска/бэкапа/импорта, `LOGIN_MAX_ATTEMPTS`/`IMPORT_MAX_ATTEMPTS`;
- HSTS в production, `X-Robots-Tag: noindex`, `X-Content-Type-Options`, `X-Frame-Options: DENY`,
  `Referrer-Policy: same-origin`, `Permissions-Policy`, отключён `X-Powered-By`;
- `BIND_HOST=127.0.0.1` + reverse proxy с HTTPS (Caddy/nginx), `TRUST_PROXY` валидируется;
- сессии в SQLite, случайный bootstrap-пароль в консоль, смена пароля, last-admin guard.

## 5. Данные и восстановление

- `data/dossier.db` (SQLite, WAL) + `data/backup-pre-sqlite-*`, `data/backup-pre-docs-*` — архивы до миграций;
- `npm run backup` — консистентный бэкап SQLite через backup API + JSON + (опционально) проекты, ротация;
- ежедневный бэкап: `deploy/install-backup-task.ps1` (Windows) или cron/таймер (Linux);
- экспорт/импорт метаданных: админка → «Обзор» → «Экспорт»/«Импорт» (JSON, подтверждение `REPLACE`);
- процедура восстановления описана в `deploy/README.md`.

## 6. Известные ограничения

- HTTPS настраивается на хосте (домен/сертификат); в репозитории — готовые конфиги Caddy/nginx.
- Darcus требует локального Ollama и моделей (`gemma4:e4b`, `nomic-embed-text`); без них остальные
  функции работают, в админке виден статус моделей.
- CI-workflow готов, но требует GitHub-репозитория для фактического запуска.
- Приложение рассчитано на один процесс Node (SQLite + in-memory SSE); горизонтальное
  масштабирование не предусмотрено.
- Нет MFA/SSO и внешнего аудита безопасности — для публичного интернета рекомендуется пройти
  внешний пентест.
