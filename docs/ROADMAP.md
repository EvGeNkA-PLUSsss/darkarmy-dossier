# DarkArmy Dossier — аудит и план развития

Дата: 2026-11-25. Проверялось на живой копии проекта (`F:\DarkArmy\DarkArmyDossier`) в изолированном песочном инстансе (порт 7562, копия `data/` и проектов, ничего в рабочей копии не менялось).

## 1. TL;DR

- Это уже не заготовка, а большой работающий продукт: **121 API-endpoint**, ~13 300 строк рукописного кода (server 3 330, app.js 4 272, admin.js 917, darcus.js 1 058, CSS 1 914, HTML ~1 200), 9 объявленных зависимостей и 175 пакетов в `node_modules`.
- Функционально сервис сильный: проекты и роли, файлы и предпросмотр, совместное редактирование, чаты/тикеты/жалобы, корзина, шары, реклама, подписки, админка и локальный ИИ-ассистент Darcus (RAG, OCR, TTS/STT, генерация документов).
- Главные проблемы — не «мало фич», а **надёжность, безопасность, структура DOM и качество кода**: нет git/тестов/бэкапов; подтверждены stored XSS (через `.shtml` и через XLSX), потеря данных в соредакторе и черновиках; из-за незакрытых тегов на телефоне модалки открываются за экраном; ИИ-модуль на 3/4 неработоспособен; интерфейс несистемный.
- Оценка полного цикла «довести до продукта»: **26–41 рабочих дня** (≈5–8 недель). Быстрый, но честный MVP «стабильно + безопасно + красиво»: **16–25 дней** (≈3–5 недель). Точечный «пожарный» ремонт критичного: **5–7 дней**.
- Порядок работ: сначала страховка (git/бэкапы/тесты) и P0-безопасность/данные → потом архитектура и интерфейс → потом новые функции.

## 4. Технические риски и долги

1. **Монолит**: `server.js` — 3 330 строк и 121 роут в одном файле; `app.js` — 4 272 строки и 195 top-level функций. Любая правка требует держать в голове весь файл.
2. **Нет границы тестируемости**: `app.listen()` вызывается на импорте, `server.js` ничего не экспортирует → supertest/изолированный запуск невозможны без рефакторинга. `DATA_DIR`/`PROJECTS_ROOT` жёстко привязаны к `__dirname`/`F:/Проекты`.
3. **Тестов нет вообще**: `test.py` — это JS с расширением `.py`, он падает (`keywordSearch` async без await), ассертов нет.
4. **Хранилище**: JSON-файлы + кэши в памяти процесса, без транзакций, версионирования схемы и миграций. Потолок — единицы одновременных пользователей и десятки МБ данных.
5. **Зависимости**: `package.json` не соответствует `package-lock`/`node_modules`; `pino` используется опционально, но не объявлен; `main` указывает на несуществующий `index.js`; нет `engines`, нет `test`.
6. **Нет эксплуатационной обвязки**: `start.bat` = `npm start`, нет README/`.env.example`, HTTPS, автозапуска, бэкапов, мониторинга; `PROJECTS_ROOT` по умолчанию `F:/Проекты` — Windows-only.
7. **Внешний рантайм**: браузерные библиотеки с CDN (marked без версии, DOMPurify, mammoth, xlsx) — офлайн-инстанс и supply-chain риск.
8. **Права на файлы**: ACL показывает `Authenticated Users: Modify` на `data/` и `F:\Проекты` — любой локальный пользователь читает хеши/телеметрию и может подменить JSON.

## 6. Предлагаемый план по этапам

### Этап 0. Страховка (1–2 дня)

**Приёмка:** свежий клон запускается по README; `git status` чист; тест-restore бэкапа проходит.

### Этап 1. P0-ремонт и быстрые победы (5–7 дней)

0. **Быстрые победы (полдня)**: закрыть `</aside>`/`</div>` и вынести модалки/lightbox в `body` (возвращает мобильные модалки), обернуть `sheet_to_html` в `sanitize()`, запинить CDN-версии + SRI + lazy-load `xlsx`/`mammoth`, обновить DOMPurify и SheetJS.
1. Отдача файлов: allow-list инлайн-типов (`png/jpg/jpeg/gif/webp/pdf`, текст как `text/plain`), всё остальное `Content-Disposition: attachment`, `nosniff`, CSP без `unsafe-inline` (инлайн-скрипты login → внешний файл/nonce).
2. SSE: `edit-change` только участникам сессии; проектные события — участникам проекта; лимит и очистка мёртвых клиентов.
3. Доступ: владелец вложения/контейнер, запрет снятия/удаления последнего админа, `requireSelfAdmin` без привязки к нику.
4. Аутентификация: убрать `admin123` (генерация случайного в консоль + принудительная смена), не логировать пароль, `TRUST_PROXY` → boolean, `NODE_ENV=production` + фиксированный `SESSION_SECRET` в `.env`, файловое/SQLite хранилище сессий.
5. Данные: `saveJSON` через tmp+fsync+rename, `.bak`, fail-fast при битом JSON, `schemaVersion`; убрать дубли записей.
6. Редактор/черновики: не откатывать `baseline` при `leave`/обрыве, `dirty`/`savedAt`, явная кнопка «Отменить», flush последнего содержимого; draft по ключу `(projectId, path)`, не удалять до успеха, не обрезать молча; закрывать inline-сессию до смены проекта; один редактор.
7. Гонки и потеря действий: request-token/`AbortController` для `openFile`, поиска, проекта, тикета; сброс `scrollTop`; не очищать чат/вложения до успешного ответа; report берёт путь из модалки.
8. Гигиена: лимит полей телеметрии, фильтр 304/статики из access-log, батчевая запись, лимиты `/api/changes`, cleanup temp при 403, rate-limit `image-analyze`, фикс двойного декодирования.

**Приёмка:** PoC S1–S8 из аудита закрыты; мобильные модалки видны (Playwright-проверка `getBoundingClientRect`), XLSX-пейлоад не исполняется; регрессионные тесты на XSS/права/SSE/данные зелёные; бэкап восстанавливается.
